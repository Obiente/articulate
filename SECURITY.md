# Security

Please use [private vulnerability reporting](https://github.com/Obiente/articulate/security/advisories/new). Do not include tokens, private transcripts, or recordings in public issues.

The latest published version is supported for security fixes. Local text and settings are plaintext under the user's application-data directory. Anyone with access to that Windows account may access those files.

Discord integrations are optional. The Vencord companion and Articulate authenticate each other over loopback with an HMAC challenge-response on a shared pairing key; the key itself never crosses the socket, the companion sends nothing until Articulate has proven possession, and the port is reserved exclusively so no other local socket can share it. The session that results is bound to the connection that completed the handshake: if the companion ever finds itself on a new connection, for example after Articulate restarts or another program takes the port in between, it pairs again from scratch before sending any voice metadata or audio. Compatibility errors (an old companion still sending its key, or an unsupported protocol version) are answered on that connection only; they can set the update notice in Settings while nothing is paired, but never replace a paired companion's state or stop a capture. The key can be rotated or forgotten from Settings, which invalidates every companion holding the old key.

The pairing key is published for the companion in a small plaintext file, `discord-pairing.json`, in Articulate's data directory, even when encryption at rest is on. Encryption at rest protects transcripts and preferences with user-scope DPAPI, which keeps them from other accounts and from offline copies of the disk. The companion runs under the same Windows account, where DPAPI adds no protection, and it cannot decrypt sealed settings without a native module or a PowerShell call, so the key is kept where that account can read it. The key authorizes nothing but the loopback connection: it cannot decrypt history or preferences, and it is only useful on this machine while the user is signed in and Articulate is running, where a program under the same account could already observe Discord directly. Earlier versions kept the key in plaintext settings, so the file does not widen what was exposed before. Forgetting the pairing removes the file.

The debugger route exposes Discord's local developer interface on a loopback TCP port chosen at random for each relaunch. While it is open, any program running under the same Windows account can read or control that Discord window, including messages and account storage. Articulate shows a notice while it knows the debugger is open and offers to restart Discord without it; restart Discord normally when you are done. Neither route requests account tokens or message history.

Meeting detection for Teams, Zoom and Google Meet is off by default. It reads the local process list and Windows audio session state only; it never joins, reads or records a meeting by itself, and transcripts start through the same path as Discord's automatic capture.

Companion build dependencies are installed with lifecycle scripts disabled, and all verified downloads use HTTPS only and are streamed to a temporary file while their SHA-256 digest is checked.

Updates trust this repository's HTTPS GitHub release metadata and asset digest. Current Windows binaries are not Authenticode-signed. A SHA-256 digest verifies bytes; it is not a Windows publisher certificate.
